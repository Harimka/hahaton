# Архитектурный референс и перенос на STM32

## Назначение

`abs-3_console_fw` служит референсом устройства слоев, внедрения зависимостей и организации C++ firmware. Целевая реализация Team-04 использует STM32G474RE и собственные контракты. Совместимость с API ztlib не является требованием.

Локальный путь сопровождающего: `C:\Users\zeets\VScode\abs-3_console_fw`. Другие участники не обязаны иметь этот каталог. Ссылки на библиотеки: https://github.com/garou-g/ztlib и https://github.com/garou-g/ztgd32 . Для воспроизводимого переноса записывайте конкретный commit исходной библиотеки и путь файла.

## Что изучать в референсе

| Источник относительно abs-3_console_fw | Что использовать |
|---|---|
| `components/ztlib/include/periph/basedrv.h` | Разделение интерфейса и реализации, жизненный цикл драйвера |
| `components/ztlib/include/periph/serialdrv.h` | Общие операции транспорта; оценивать семантику перед переносом |
| `components/ztlib/include/periph/spi.h` | Абстракция SPI без типов конкретного MCU |
| `components/ztlib/cpu/gd32/spi.h` | Реализация интерфейса платформенным адаптером, буферы фиксированного размера |
| `components/ztlib/cpu/esp32/spi.h` | Второй адаптер для той же абстракции |
| `CMakeLists.txt` | Разделение компонентов и ARM-артефактов; конфигурация относится к GD32F407VG |

В изученных адаптерах представлены GD32 и ESP32. Их существование не подтверждает наличие готового порта STM32. Файлы startup, linker script, IRQ, RCC, DMA и настройки GPIO для GD32 нельзя подключать как реализацию STM32G474RE.

## Правила выбора реализации

1. Сначала изучите существующий код Team-04 и его потребителей. Используйте действующий интерфейс, если он покрывает задачу.
2. Из референса переносите понятный паттерн или небольшой независимый компонент. Для SPI FIFO/DMA отдельно нужны полный дуплекс, время жизни буферов, завершение/отмена, ошибки и владение CS. Сходство имен методов не доказывает эквивалентность этих требований.
3. Не добавляйте `BaseDrv`, `void*`-конфигурацию, универсальный `ioctl`, RTOS или ETL только ради сходства с референсом. Каждая зависимость должна решать конкретную задачу.
4. STM32 HAL/LL, аппаратные дескрипторы и обработчики IRQ принадлежат `firmware/Drivers/port/`. Алгоритмы событий и SRS собираются на ПК без HAL.
5. При копировании кода сохраняйте исходные copyright, авторство и лицензию. У изученной ztlib лицензия MIT; лицензии других компонентов проверяются отдельно. Требование `@author team-04` относится к собственному коду и не заменяет авторство заимствованного.
6. В описании изменения укажите источник и commit, что перенесено, что адаптировано и как проверено. Если использован только архитектурный подход, обозначьте это прямо.

## Известная граница интеграции

На момент проверки `firmware/Drivers/bsp/Inc/imudrv.h` содержит 15-байтный `ImuRawSample`: сначала `timestampUs`, затем `sampleIndex`; `ImuFlag` использует биты 0/1/2 для overrun/saturation/SPI error. `docs/interfaces.md` описывает другую 16-байтную структуру, порядок полей и биты флагов. `static_assert` размера в заголовке не проверяет соответствие документации.

До интеграции владелец контракта должен выбрать одну внутреннюю структуру и синхронно обновить потребителей, документ и проверки. Не сериализуйте внутреннюю структуру напрямую как SHK1 и не преобразуйте флаги простым копированием битов. Это известное расхождение, а не разрешение каждому агенту выбирать свою версию.
