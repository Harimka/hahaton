## 1. Строгие правила детектирования и границы кадра

* **Условие триггера:** Строгое превышение динамического ускорения:
  $$\max(|a_{x, dyn}|, |a_{y, dyn}|, |a_{z, dyn}|) > 3.0g$$
* **Границы кадра события:**
  - Находится пиковый максимум по осям события: $A_{\max} = \max_{t} |a(t)|$.
  - Уровень отсечки: $A_{cut} = 0.25 \cdot A_{\max}$.
  - Начало значащей части кадра: первый отсчет перед пиком, где $|a(t)| > A_{cut}$.
  - Конец значащей части кадра: последний отсчет после затухания, где $|a(t)| > A_{cut}$.
  - **Запас фронтов:** К началу и концу кадра добавляется фиксированный защитный интервал в 20 отсчетов ($\approx 3.0$ мс), гарантирующий сохранение фронта нарастания импульса.
* **Лимит длительности кадра:** Максимальная длительность одного кадра — **30 секунд** ($\approx 200\,000$ отсчетов). Если процесс не затухает дольше 30 с, запись принудительно завершается с выставлением флага `TRUNCATED`.

## 2. Диагностика FIFO и отсчётов датчика (в ОЗУ прошивки)

Используется для передачи данных из прерывания / DMA драйвера акселерометра в кольцевой буфер и FSM.

```cpp
#pragma pack(push, 1)
struct ImuRawSample {
    uint32_t sampleIndex;   ///< Сквозной программный счетчик отсчетов
    uint32_t relTimeUs;     ///< Время отсчета относительно старта текущего кадра (us)
    int16_t  rawX;          ///< Сырое значение X (чувствительность 0.488 mg/LSB при ±16g)
    int16_t  rawY;          ///< Сырое значение Y
    int16_t  rawZ;          ///< Сырое значение Z
    uint8_t  flags;         ///< Битовые флаги диагностик:
                            ///< Bit 0: FLAG_FIFO_FULL (опасное состояние: FIFO_STATUS2 FIFO_FULL_SMART)
                            ///< Bit 1: FLAG_FIFO_OVERRUN (подтвержденная потеря: FIFO_STATUS2 OVER_RUN)
                            ///< Bit 2: FLAG_SATURATION_16G (выход за пределы шкалы ±16g)
                            ///< Bit 3: FLAG_SPI_READ_ERROR (ошибка шины / таймаут)
                            ///< Bit 4: FLAG_TRUNCATED (кадр усечен по лимиту времени/буфера)
    uint8_t  reserved;      ///< Выравнивание структуры
};
#pragma pack(pop)
```

## 3. Формат бинарного файла сигнала на SD (`raw_signal_XXXX.bin`) — Спецификация SHK1 v1.1

Имя файла: `raw_signal_XXXX.bin`, где `XXXX` — метка времени начала кадра (timestamp в миллисекундах от старта системы).

### Заголовок файла (48 байт, Little-Endian):
```cpp
#pragma pack(push, 1)
struct RawSignalFileHeader {
    char     magic[4];              ///< [0..3]   "SHK1" (Shock Format)
    uint16_t version;               ///< [4..5]   0x0002 (версия формата v1.1 с 48-байтным заголовком)
    uint16_t headerSize;            ///< [6..7]   48 байт
    float    sampleRateHz;          ///< [8..11]  6660.0f (номинал стенда)
    float    scaleFactorG;          ///< [12..15] 0.000488f (перевод LSB в g)
    uint32_t eventId;               ///< [16..19] Порядковый номер зарегистрированного удара
    uint32_t sampleCount;           ///< [20..23] Количество отсчетов в файле
    uint32_t triggerOffsetUs;       ///< [24..27] Смещение времени первого превышения >3.0g от старта кадра
    uint32_t eventFlags;            ///< [28..31] Маска флагов события:
                                    ///<          Bit 0: FIFO_FULL (порог заполнения)
                                    ///<          Bit 1: FIFO_OVERRUN (факт потери отсчетов -> UNRELIABLE)
                                    ///<          Bit 2: SATURATED_16G (удар превысил ±16g, пик срезан)
                                    ///<          Bit 3: SPI_READ_ERROR (ошибки шины)
                                    ///<          Bit 4: TRUNCATED (кадр обрезан по тайм-ауту 30с)
                                    ///<          Bit 5: UNRELIABLE (данные помечены как недостоверные)
    uint64_t frameStartMonotonicUs; ///< [32..39] Монотонное время старта кадра в микросекундах
    uint32_t sensorLocationId;      ///< [40..43] ID точки монтажа датчика на конструкции
    uint32_t mountingMatrixId;      ///< [44..47] ID ориентации (для пересчета в строительные оси)
};
#pragma pack(pop)
```

#### Запись одного отсчёта в файле (16 байт):
```cpp
#pragma pack(push, 1)
struct RawSignalRecord {
    uint32_t timestampUs;   ///< Относительное время отсчета от начала кадра (us)
    float    ax;            ///< Ускорение X [g] (динамическое, без статической гравитации)
    float    ay;            ///< Ускорение Y [g]
    float    az;            ///< Ускорение Z [g]
};
#pragma pack(pop)
```

## 4. Формат бинарного файла спектра SRS (`raw_srs_XXXX.bin`) — Спецификация SRS1

```cpp
#pragma pack(push, 1)
struct RawSrsFileHeader {
    char     magic[4];          ///< "SRS1" (SRS Format v1)
    uint16_t version;           ///< 0x0001
    uint16_t numPoints;         ///< 94 (число точек частотной сетки от 10 до 2000 Гц)
    float    qFactor;           ///< 10.0f (добротность осцилляторов)
    uint32_t eventId;           ///< ID соответствующего удара
    uint32_t reserved[4];       ///< Выравнивание заголовка до 32 байт
};

struct RawSrsPoint {
    float fn;   ///< Собственная частота осциллятора [Гц] (по сетке CSV)
    float gx;   ///< Maximax спектральный отклик X [g]
    float gy;   ///< Maximax спектральный отклик Y [g]
    float gz;   ///< Maximax спектральный отклик Z [g]
};
#pragma pack(pop)
```

## 5. Требования к компонентам новой платы (BOM)

* **Акселерометр:**
  - Обязательное требование ТЗ: **ODR $\ge 10$ кГц**.
  - Чипы ADXL372 (6.4 кГц), ADXL375 (3.2 кГц) и H3LIS331DL (1 кГц) **СТРОГО НЕ ПОДХОДЯТ**.
  - Рекомендуемый кандидат: **IIS3DWB** (ODR 26.667 кГц, $\pm 16g$, 3 оси, SPI до 10 МГц).
* **Микроконтроллер:**
  - Обязательное требование ТЗ: наличие аппаратного контроллера **SDIO / SDMMC** для 4-битной работы с SD-картой (без абстрактных мостов).
  - Рекомендуемые МК: **STM32H743 / STM32H753** или **STM32F405 / STM32F407** с нативным SDIO.

## 6. Межтрековое взаимодействие и матрица ориентации

* **Преобразование координат в оси аппарата:**
  Нельзя просто повернуть найденные максимумы SRS матрицей. Для пересчета в оси КА сначала сырой временной вектор умножается на матрицу поворота $R$:
  $$a_{sc}[k] = R \cdot a_{sensor}[k]$$
  и затем SRS рассчитывается заново по полученным осям аппарата $a_{sc}$.
* **UART Телеметрия:** Пакеты `STATUS` и `EVENT_SUMMARY` передаются с низким приоритетом и жестким ограничением буфера. При перегрузке отбрасывается телеметрия, но ни в коем случае не отсчеты сбора данных.
