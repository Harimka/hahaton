## 1. Строгие правила детектирования и границы кадра

* **Условие триггера:** Строгое превышение динамического ускорения:
  $$\max(|a_{x, dyn}|, |a_{y, dyn}|, |a_{z, dyn}|) > 3.0g$$
* **Границы кадра события:**
  - Находится пиковый максимум по осям события: $A_{\max} = \max_{t} |a(t)|$.
  - Уровень отсечки: $A_{cut} = 0.25 \cdot A_{\max}$.
  - Начало значащей части кадра: первый отсчет перед пиком, где $|a(t)| > A_{cut}$.
  - Конец значащей части кадра: последний отсчет после затухания, где $|a(t)| > A_{cut}$.
  - **Запас фронтов:** К началу и концу кадра добавляется фиксированный защитный интервал в 20 отсчетов ($\approx 3.0$ мс), гарантирующий сохранение фронта нарастания импульса.

## 2. Контракт блока отсчёта датчика (в ОЗУ прошивки)

Используется для передачи данных из прерывания / DMA драйвера акселерометра в кольцевой буфер и FSM.

```cpp
#pragma pack(push, 1)
struct ImuRawSample {
    uint32_t sampleIndex;   ///< Сквозной счетчик отсчетов датчика (для контроля 0% потерь)
    uint32_t relTimeUs;     ///< Время отсчета относительно старта текущего кадра (us)
    int16_t  rawX;          ///< Сырое значение X (чувствительность 0.488 mg/LSB при ±16g)
    int16_t  rawY;          ///< Сырое значение Y
    int16_t  rawZ;          ///< Сырое значение Z
    uint8_t  flags;         ///< Битовые флаги диагностик:
                            ///< Bit 0: FLAG_FIFO_OVERRUN (аппаратный флаг OVER_RUN из FIFO_STATUS2)
                            ///< Bit 1: FLAG_SATURATION_16G (выход за пределы ±16g)
                            ///< Bit 2: FLAG_SPI_READ_ERROR (сбой транзакции / таймаут шины)
                            ///< Bit 3: FLAG_DATA_TRUNCATED (кадр усечен из-за переполнения буфера)
    uint8_t  reserved;      ///< Выравнивание структуры
};
#pragma pack(pop)
```

## 3. Формат бинарного файла сигнала на SD (`raw_signal_XXXX.bin`) — Версия SHK1

Имя файла: `raw_signal_XXXX.bin`, где `XXXX` — метка времени начала кадра (timestamp в миллисекундах от старта системы).

### Заголовок файла (32 байта, Little-Endian):
```cpp
#pragma pack(push, 1)
struct RawSignalFileHeader {
    char     magic[4];          ///< "SHK1" (Shock Format v1)
    uint16_t version;           ///< 0x0001
    uint16_t headerSize;        ///< 32 байта
    float    sampleRateHz;      ///< 6660.0f (судейский стенд)
    float    scaleFactorG;      ///< 0.000488f (перевод сырых LSB в g)
    uint32_t eventId;           ///< Порядковый номер зарегистрированного удара
    uint32_t sampleCount;       ///< Количество сэмплов в данном файле
    uint32_t triggerRelTimeUs;  ///< Время первого превышения >3.0g от старта кадра (us)
    uint32_t eventFlags;        ///< Диагностическая маска всего события:
                                ///< Bit 0: FIFO_OVERRUN (была потеря в аппаратном FIFO)
                                ///< Bit 1: SATURATED_16G (удар превысил ±16g, пик срезан)
                                ///< Bit 2: SPI_READ_ERROR (были ошибки шины)
                                ///< Bit 3: TRUNCATED (кадр обрезан по лимиту памяти)
                                ///< Bit 4: UNRELIABLE (данные помечены как недостоверные)
};
#pragma pack(pop)
```

#### Запись одного отсчёта в файле (16 байт):
```cpp
#pragma pack(push, 1)
struct RawSignalRecord {
    uint32_t relTimeUs;     ///< Время отсчета в микросекундах относительно старта кадра
    float    ax;            ///< Ускорение по оси X [g] (без учета статической гравитации)
    float    ay;            ///< Ускорение по оси Y [g]
    float    az;            ///< Ускорение по оси Z [g]
};
#pragma pack(pop)
```
*Защита от переполнения времени:* Использование `relTimeUs` относительно старта кадра гарантирует 100% защиту от переполнения 32-битного счетчика времени (71 минута) при длительной многодневной транспортировке.

## 4. Формат бинарного файла спектра SRS (`raw_srs_XXXX.bin`) — Версия SRS1

Имя файла: `raw_srs_XXXX.bin` (метка времени `XXXX` строго совпадает с исходным `raw_signal_XXXX.bin`).

```cpp
#pragma pack(push, 1)
struct RawSrsFileHeader {
    char     magic[4];          ///< "SRS1" (SRS Format v1)
    uint16_t version;           ///< 0x0001
    uint16_t numPoints;         ///< 94 (число точек частотной сетки от 10 до 2000 Гц)
    float    qFactor;           ///< 10.0f (добротность осцилляторов)
    uint32_t eventId;           ///< ID соответствующего удара
    uint32_t reserved[4];       ///< Выравнивание заголовка
};

struct RawSrsPoint {
    float fn;   ///< Собственная частота осциллятора [Гц] (по сетке CSV)
    float gx;   ///< Maximax спектральный отклик по оси X [g]
    float gy;   ///< Maximax спектральный отклик по оси Y [g]
    float gz;   ///< Maximax спектральный отклик по оси Z [g]
};
#pragma pack(pop)
```

## 5. Разделение частот дискретизации (Судейский стенд vs Новая плата)

1. **Судейский образец (STM32G474RE + LSM6DS3):**
   - Частота опроса: **строго 6.66 кГц** ($T_s \approx 150.15$ мкс), обусловлена аппаратным пределом LSM6DS3.
   - Метод Смолвуда и коэффициенты фильтров рассчитываются строго под $f_s = 6660$ Гц.
2. **Собственное аппаратное решение (BOM и схема новой платы):**
   - Требование ТЗ: акселерометр с **ODR $\ge 10$ кГц** (например, IIS3DWB с ODR до 26.7 кГц или ADXL372/375) и интерфейс SDIO (4-bit).
   - МК подбирается с поддержкой SDIO/SDMMC (например, STM32H7 / STM32F405 или STM32G4 с мостом).

## 6. Взаимодействие с внешними треками (Cross-Track Telemetry)

Для интеграции с треком **«Конструкция»** и **«ИИ-агент»** по интерфейсу UART/VCP реализован легковесный версионированный протокол телеметрии:

1. **Пакет `STATUS` (периодический, 1 Гц):**
   - Состояние FSM, сквозной счетчик сэмплов, счетчик переполнений FIFO (доказательство 0% пропусков для жюри), напряжение питания (основное 12В / резервная батарея).
2. **Пакет `EVENT_SUMMARY` (по факту удара):**
   - ID события, длительность, пиковые $A_{\max}$ по осям, флаги (`SATURATED`, `TRUNCATED`, `UNRELIABLE`).
   - Идентификатор точки монтажа датчика (`SensorLocationId`) для пересчета ускорений в строительные оси космического аппарата ($X_{sc}, Y_{sc}, Z_{sc}$).
3. **Пакет `SRS_SUMMARY` (по окончании расчета):**
   - Идентификатор превышения критической кривой, резонансная частота $f_{\text{res}}$ с максимальным спектральным откликом.
